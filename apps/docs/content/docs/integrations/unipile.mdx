## OAuth scopes [#oauth-scopes]

Sim requests no OAuth scopes for LinkedIn (Unipile). For a self-hosted deployment, register your own app with the provider using the settings below. See [Integrations and OAuth](/platform/self-hosting/integrations-oauth) for setup.

| Setting | Value |
| ------- | ----- |
| Environment variables | `UNIPILE_API_KEY` |

## Use the block [#usage-instructions]

Shared workspaces list public LinkedIn accounts from `outreach_user_connections_v1` plus your personal connections via Unipile hosted authentication (`GET /api/unipile/accounts`). Other workspaces connect LinkedIn via hosted authentication only. Uses `UNIPILE_API_KEY` from the deployment environment. Covers LinkedIn company and user profiles, posts, comments, reactions, search, messaging, relations, and attachments.

## Actions

### Unipile Comment a post

Comments on a post or replies to a comment (`POST /api/v1/posts/\{post_id\}/comments`, multipart). LinkedIn: `post_id` is the post social_id; optional `mentions` is a JSON array of \{ name, profile_id, is_company? \} for `\{\{n\}\}` placeholders in text (the Unipile block uses a mention table to build this). See https://developer.unipile.com/docs/posts-and-comments Uses server UNIPILE_API_KEY.

<ReferenceDetails>

#### Input

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `post_id` | string | Yes | Post id path param. LinkedIn: social_id from the post object. Instagram: provider_id \(not post short code\). |
| `account_id` | string | Yes | Unipile account id \(multipart field\) |
| `text` | string | Yes | Comment \(max 1250\). LinkedIn: `\{\{n\}\}` = nth entry in `mentions` — e.g. Hey \{\{0\}\}, check this out! |
| `mentions` | string | No | Optional LinkedIn JSON array like Unipile docs: \[\{ "name": "…", "profile_id": "…" \}\]. The proxy sends a real JSON `mentions` array \(no file parts\) or an `application/json` multipart part when attachments are uploaded. Use `\{\{0\}\}`, `\{\{1\}\}` in `text` in the same order. |
| `name` | string | No | Legacy: single-mention display name \(prefer `mentions` JSON or block table\) |
| `profile_id` | string | No | Legacy: single-mention profile_id |
| `is_company` | string | No | Legacy: true/false with name+profile_id |
| `external_link` | string | No | LinkedIn only: https URL for link preview; URL should also appear in text. |
| `as_organization` | string | No | LinkedIn only: organization id to comment as that org. |
| `comment_id` | string | No | Optional: reply to this comment. LinkedIn: id from the comments list. |
| `attachments` | json | No | Optional files as UserFile array \(multipart `attachments` parts, same as send message / create post\). Legacy string still accepted. |

#### Output

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `object` | string | Unipile object type \(e.g. CommentSent\) |
| `comment_id` | string | Created comment id |

</ReferenceDetails>

### Unipile Retrieve a profile

Retrieves a user profile (`GET /api/v1/users/\{identifier\}`). Required: `account_id`, `user_identifier` (path). Optional LinkedIn queries: `linkedin_sections` (JSON array string—avoid `*` for high volume; see throttling), `linkedin_api` (recruiter | sales_navigator), `notify` (boolean; profile visit notification). Consult provider limits: https://developer.unipile.com/docs/provider-limits-and-restrictions Uses server `UNIPILE_API_KEY`.

<ReferenceDetails>

#### Input

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `account_id` | string | Yes | Unipile account id \(required query parameter\) |
| `user_identifier` | string | Yes | Path `\{identifier\}`: provider internal id or public id \(e.g. LinkedIn public slug\) |
| `linkedin_sections_json` | string | No | Optional JSON array of LinkedIn profile section names for Unipile `linkedin_sections` \(e.g. `\["experience_preview","skills"\]`\). Prefer preview or targeted sections; `*` is heavy and easy to throttle. |
| `linkedin_api` | string | No | Optional `linkedin_api` query: recruiter \| sales_navigator \(when subscribed\) |
| `notify` | boolean | No | Optional `notify` query: whether the profile visit is notified to the viewee |

#### Output

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `object` | string | Unipile object type \(e.g. UserProfile\) |
| `provider` | string | Provider id |
| `public_identifier` | string | Public slug |
| `first_name` | string | First name |
| `last_name` | string | Last name |
| `headline` | string | Headline |
| `public_profile_url` | string | Public profile URL |
| `throttled_sections` | json | When LinkedIn throttles section payloads, Unipile lists affected section names \(if any\) |
| `profile` | json | Full user profile payload |

</ReferenceDetails>

### Unipile Perform Linkedin search

Runs LinkedIn Classic, Sales Navigator, or Recruiter search (`POST /api/v1/linkedin/search`). Pass `search_body` as a JSON string built from api, category, keywords, filters, optional `\{ url \}`, etc. Use Retrieve LinkedIn search parameters for filter IDs. Guide: https://developer.unipile.com/docs/linkedin-search Query: account_id (required), optional cursor, limit (0–100; Classic should stay ≤50). Uses server UNIPILE_API_KEY.

<ReferenceDetails>

#### Input

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `account_id` | string | Yes | Unipile account id \(required query parameter\) |
| `search_body` | string | Yes | JSON string for the POST body: classic people/companies/posts/jobs, sales_navigator, recruiter, \{ "url": "…" \} to search from a public URL, or \{ "cursor": "…" \} for a long cursor in the body. |
| `cursor` | string | No | Optional cursor query param for pagination \(short cursors\) |
| `limit` | number | No | Optional result limit 0–100 \(Unipile default 10\). Sales Navigator / Recruiter up to 100; LinkedIn Classic should not exceed 50. |

#### Output

| Parameter | Type | Description |
| --------- | ---- | ----------- |
| `object` | string | Unipile object type \(e.g. LinkedinSearch\) |
| `item_count` | number | Number of search results in this page |
| `items` | json | Search result items |
| `cursor` | string | Next page cursor |
| `paging` | json | Paging metadata |
| `config` | json | Echoed search config when present |
| `metadata` | json | Search metadata \(history/context/request ids\) when present |

</ReferenceDetails>
